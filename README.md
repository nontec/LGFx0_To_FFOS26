# LG Fx0 LGL25 (au/KDDI): обновление Firefox OS 2.0.0 до 2.6

Гайд для Windows и японского операторского LG Fx0 LGL25, кодовое имя madai. Основан на сохранённом журнале успешной установки на нашем аппарате. Телефон во время подготовки этого документа не изменялся.

Это установка архивной неофициальной сборки Firefox OS 2.6, а не официальное обновление LG. Она не содержит современный Firefox 140. В используемом архиве application.ini сообщает 46.0a1, platform.ini - 47.0a1, BuildID 20160218030207. Это не ошибка загрузки архива. Современные сайты могут не работать даже после успешной установки.

## 1. Область применения и необходимые файлы

Проверенная исходная система нашего аппарата:

- модель LG Fx0 LGL25, оператор au/KDDI;
- Firefox OS 2.0.0;
- Platform version 32.0;
- Build identifier 20141125231350.

Для другой модели или существенно другой прошивки команды записи разделов нельзя переносить без проверки.

Зарядите телефон желательно до 70% или выше. Подготовьте исправный USB-кабель, стабильный USB-порт и не менее 15 ГБ свободного места для резервных копий. Скопируйте фотографии, контакты и другие важные данные отдельно. Обновление создаёт новый профиль системы: приложения и настройки старого профиля автоматически не сохраняются.

Нужны:

| Путь | Назначение |
|---|---|
| tools\platform-tools\adb.exe и fastboot.exe | Связь с телефоном |
| research\libs\armeabi-v7a\dirtycow | Временное получение root на проверенной старой прошивке |
| research\libs\armeabi-v7a\run-as | Вспомогательная root-оболочка |
| firmware\twrp_2870-madai-a01-recovery.img | Проверенный временный TWRP для madai |
| firmware\fx0-b2g26-prepared.tar.gz | Подготовленные Gecko и Gaia 2.6 для /system/b2g |
| firmware\fxup.zip | Исправления совместимости Fx0, включая boot, Bluetooth и NFC |
| research\install26.sh | Проверенный скрипт установки из TWRP |

Подготовленный tar.gz - наш промежуточный установочный архив, не ZIP для кнопки Install в TWRP. Скрипт install26.sh рассчитан именно на него. Не подменяйте его исходным архивом Gecko.

Архивные исходники и инструкция сообщества: https://github.com/stephanfriedrich/ffos_on_lgfx0 . Там лежат Gaia, Gecko, fxup и материалы по fastboot/TWRP. Наш путь отличается: используется временный запуск TWRP и подготовленный архив вместо выполнения старого shallow_flash.sh в Windows.

В подготовленном архиве Gecko объединён с Gaia: webapps помещены в b2g/webapps, settings.json - в b2g/defaults, user.js - в b2g/defaults/pref с преобразованием user_pref в pref. Права Unix сохранены в tar. Простое копирование распакованной Windows-папки не равноценно этой подготовке.

## 2. Контрольные суммы

Откройте PowerShell. Все дальнейшие команды с adb и fastboot выполняются из одной сессии:

```powershell

$adb = 'D:\Fx0\tools\platform-tools\adb.exe'
$fastboot = 'D:\Fx0\tools\platform-tools\fastboot.exe'
Get-FileHash .\firmware\twrp_2870-madai-a01-recovery.img -Algorithm SHA256
Get-FileHash .\firmware\fx0-b2g26-prepared.tar.gz -Algorithm SHA256
```

## 3. Подключение и драйверы

Включите отладку в настройках разработчика Firefox OS. Если есть выбор режима, включите ADB. Подключите телефон и выполните:

```powershell
& $adb devices
```

Должна появиться строка с серийным номером и статусом device. Если телефон просит разрешить подключение отладчика - разрешите.

Если устройство не обнаружено, проверьте кабель, USB-порт и Диспетчер устройств Windows. Для работающей системы нужен ADB Interface, для fastboot - Android Bootloader Interface. Это разные USB-режимы: наличие рабочего ADB не означает, что установлен драйвер fastboot.

Если Windows пишет «не удалось найти драйверы», автоматический поиск ничего не гарантирует. Используйте подписанный совместимый драйвер LG либо Android для фактического оборудования. Папка tools\usb_driver содержит Google USB Driver, но его INF не обязан содержать USB ID LG. Не выбирайте случайный несовместимый драйвер и не отключайте проверку подписи только ради продолжения гайда.

Проверка версии:

```powershell
& $adb shell cat /system/b2g/application.ini
& $adb shell cat /system/b2g/platform.ini
& $adb shell getprop ro.product.model
```

Если подключено несколько Android-устройств, отключите остальные, чтобы команды не попали на другой телефон.

## 4. Получение временного root

Сначала попробуйте:

```powershell
& $adb root
& $adb wait-for-device
& $adb shell id
```

Если вывод содержит uid=0, эксплойт не нужен. Иначе на проверенной операторской прошивке использовался Dirty COW, изменяющий /system/bin/run-as. Это эксплуатация уязвимости старой системы; для другой сборки результат не гарантирован.

Сохраните оригинал run-as именно с обновляемого телефона, до применения эксплойта. Для каждой установки создавайте новый каталог резервной копии:

```powershell
$backup = Join-Path 'D:\Fx0' ('stock-backup-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $backup
& $adb pull /system/bin/run-as "$backup\run-as-original"
& $adb push .\research\libs\armeabi-v7a\dirtycow /data/local/tmp/fx0-dcow
& $adb push .\research\libs\armeabi-v7a\run-as /data/local/tmp/fx0-run-as
& $adb shell chmod 755 /data/local/tmp/fx0-dcow /data/local/tmp/fx0-run-as
& $adb shell /data/local/tmp/fx0-dcow /data/local/tmp/fx0-run-as /system/bin/run-as --no-pad
& $adb shell /system/bin/run-as
```

В открывшейся оболочке выполните `id`. Продолжайте только если получен uid=0. При зависании или неудаче не запускайте команды записи разделов. После перезагрузки временный root может потребовать повторного получения.

Если защита Windows блокирует эксплойт, не отключайте защиту всей системы. Сначала проверьте происхождение файлов. При осознанном использовании можно ограничить временное исключение отдельной папкой с этими инструментами и убрать его после работы.

Если root уже был доступен через adb, создайте переменную $backup и новый каталог приведёнными выше командами и также сохраните оригинальный run-as; загрузка эксплойта не требуется.

## 5. Сохранение LAF и исходных разделов до изменения fastboot

Следующие команды - команды оболочки ТЕЛЕФОНА с uid=0, не PowerShell. Если root через ADB, войдите `& $adb shell`; если через эксплойт - `& $adb shell /system/bin/run-as`.

```sh
ls -l /dev/block/platform/msm_sdcc.1/by-name/laf
readlink -f /dev/block/platform/msm_sdcc.1/by-name/laf
blockdev --getsize64 /dev/block/platform/msm_sdcc.1/by-name/laf
```

На проверенном аппарате LAF соответствовал mmcblk0p27, размер 33554432 байта, то есть 32 МиБ. Если размер или разметка отличаются, остановитесь: числовой раздел нельзя угадывать.

Сохраните LAF:

```sh
dd if=/dev/block/platform/msm_sdcc.1/by-name/laf of=/data/local/tmp/fx0-laf-original.img bs=1048576
chmod 644 /data/local/tmp/fx0-laf-original.img
md5sum /data/local/tmp/fx0-laf-original.img
exit
```

В PowerShell:

```powershell
& $adb pull /data/local/tmp/fx0-laf-original.img "$backup\laf.img"
(Get-Item "$backup\laf.img").Length
Get-FileHash "$backup\laf.img" -Algorithm MD5
Get-FileHash "$backup\laf.img" -Algorithm SHA256
```

Размер должен быть 33554432, MD5 на компьютере и телефоне должны совпасть. Сумма LAF другого владельца здесь не подходит.

До изменения LAF аналогично сохраните boot, recovery и system. Для каждого раздела отдельно в root-оболочке выполните, подставляя его имя вместо NAME:

```sh
dd if=/dev/block/platform/msm_sdcc.1/by-name/NAME of=/data/local/tmp/fx0-NAME.img bs=1048576
chmod 644 /data/local/tmp/fx0-NAME.img
md5sum /data/local/tmp/fx0-NAME.img
```

Затем выйдите в PowerShell, скачайте файл и сравните MD5:

```powershell
& $adb pull /data/local/tmp/fx0-NAME.img "$backup\NAME.img"
Get-FileHash "$backup\NAME.img" -Algorithm MD5
```

NAME - шаблон, не буквальное имя. После проверки копии временный файл можно удалить с телефона, прежде чем снимать следующий большой раздел. Если на /data недостаточно места для system, сначала освободите место от собственных файлов; не считайте незавершённый dd резервной копией.

Дополнительно полезно сохранить modem, modemst1, modemst2, persist, fsg, factory, aboot и abootb тем же способом. Это индивидуальные данные и загрузочные разделы: храните их приватно и не прошивайте копии от чужого телефона. Обычное обновление ниже их не изменяет.

В копии system, снятой после Dirty COW, run-as уже может быть изменён. Поэтому отдельно сохранённый оригинал обязателен.

## 6. Открытие fastboot на операторском Fx0

На нашем операторском аппарате доступ к fastboot был открыт обнулением LAF после проверенного резервного копирования. Это убирает штатный обработчик LG Download Mode, а не выполняет обычную команду разблокировки загрузчика.

Только после проверок раздела из предыдущего пункта войдите в root-оболочку и выполните:

```sh
dd if=/dev/zero of=/dev/block/platform/msm_sdcc.1/by-name/laf bs=1048576 count=32
sync
exit
```

Команда намеренно записывает ровно 32 МиБ. Не заменяйте путь на весь mmcblk0. Если fastboot уже открыт, повторять обнуление не нужно.

Полностью выключите телефон, отсоедините USB, зажмите Volume + и подключите USB к компьютеру. На нашем Fx0 команда adb reboot bootloader приводила к обычной загрузке системы, поэтому использовался этот ручной вход.

В PowerShell:

```powershell
& $fastboot devices
& $fastboot getvar product
```

Проверенное значение product - MADAI. Если fastboot ничего не видит, сначала решите вопрос драйвера Android Bootloader Interface.

Не выполняйте fastboot flashing unlock или fastboot oem unlock по аналогии с современными телефонами: в проверенной процедуре они не использовались.

## 7. Временный запуск TWRP

```powershell
& $fastboot boot .\firmware\twrp_2870-madai-a01-recovery.img
```

Дождитесь интерфейса TWRP и проверьте:

```powershell
& $adb devices
& $adb shell id
```

Должен быть recovery и root. Этот запуск не заменяет раздел recovery. Если временный запуск не работает, не переходите автоматически к прошивке другого recovery: сначала проверьте модель, образ и вывод fastboot.

Разрешите запись System в TWRP, когда будете переходить к установке. Не выполняйте Format Data или Wipe System.

## 8. Полная резервная копия перед установкой

В TWRP снимите резервную копию Boot, System и Data на microSD, затем скопируйте весь каталог TWRP/BACKUPS на компьютер. Убедитесь, что копирование прошло без ошибок. TWRP обычно не включает содержимое внутренней общей памяти /data/media в стандартный бэкап Data: фотографии и прочие файлы сохраните отдельно.

Для точного отката можно дополнительно снять сырые образы boot, system и userdata из временного TWRP. Перед чтением system/userdata отключите монтирование System и Data в меню Mount и проверьте `adb shell mount`: соответствующие разделы не должны быть смонтированы. Не делайте это одновременно с резервным копированием TWRP.

```powershell
& $adb pull /dev/block/platform/msm_sdcc.1/by-name/boot "$backup\boot-before26.img"
& $adb pull /dev/block/platform/msm_sdcc.1/by-name/system "$backup\system-before26.img"
& $adb pull /dev/block/platform/msm_sdcc.1/by-name/userdata "$backup\userdata-before26.img"
```

Проверяйте размер через blockdev --getsize64 и контрольную сумму на обеих сторонах, например:

```powershell
& $adb shell md5sum /dev/block/platform/msm_sdcc.1/by-name/system
Get-FileHash "$backup\system-before26.img" -Algorithm MD5
```

Проделайте это для всех трёх образов. userdata может содержать все личные данные, включая общую память. Храните копии приватно. Не используйте перенаправление `adb shell ... > image.img` для бинарного бэкапа: старый ADB/оболочка Windows могут изменить байты. Используйте adb pull.

## 9. Установка Firefox OS 2.6

В TWRP смонтируйте System и Data. Убедитесь, что /system - именно системный раздел телефона, а не пустой каталог:

```powershell
& $adb shell mount
& $adb shell cat /system/b2g/application.ini
& $adb shell df /system
```

Скрипт временно оставляет старый каталог b2g рядом с новым. Поэтому на /system нужно место под оба; если его нет, не удаляйте исходную систему до проверки полного бэкапа и пересмотра процедуры.

Загрузите файлы во временную память recovery:

```powershell
& $adb push .\firmware\fx0-b2g26-prepared.tar.gz /tmp/fx0-b2g26-prepared.tar.gz
& $adb push .\firmware\fxup.zip /tmp/fxup.zip
& $adb push .\research\install26.sh /tmp/install26.sh
& $adb push "$backup\run-as-original" /tmp/run-as-original
```

Проверьте успешное завершение каждой передачи. /tmp очищается после перезагрузки: при повторном входе файлы нужно передать снова.

Запустите:

```powershell
& $adb shell sh /tmp/install26.sh
```

Скрипт выполняет следующие действия:

1. Сохраняет старый /system/b2g как /system/b2g-stock-2.0.
2. Распаковывает подготовленные Gecko и Gaia в /system/b2g.
3. Перемещает старый профиль и приложения из используемых системой каталогов в /data/fx0-pre26-live, чтобы новая Gaia начала с чистых настроек.
4. Возвращает исходное содержимое /system/bin/run-as.
5. Запускает установщик fxup.zip: заменяет boot и файлы совместимости Bluetooth/NFC, устанавливает анимацию загрузки.

То есть boot действительно изменяется, хотя recovery остаётся прежним. Отдельно устанавливать fxup.zip второй раз не требуется.

Не ориентируйтесь только на завершающее Done: старый установщик fxup не останавливается на каждой ошибке. Проверьте журнал на ошибки dd, нехватку места, ошибки распаковки и отсутствующие файлы. После сбоя не запускайте install26.sh повторно вслепую: наличие b2g-stock-2.0 намеренно блокирует повторный запуск.

Проверки до перезагрузки:

```powershell
& $adb shell ls -l /system/b2g/b2g /system/b2g/plugin-container /system/b2g/updater
& $adb shell ls -l /system/b2g/webapps/webapps.json
& $adb shell cat /system/b2g/platform.ini
& $adb shell sync
```

У b2g, plugin-container и updater должны быть права исполнения. platform.ini должен соответствовать сборке из раздела 1. Если установщик завершился ошибкой, сначала выясните её причину или восстановите резервную копию.

В нашей временной TWRP встречалась рекурсия вызова modprobe. Только если проявилась именно эта ошибка, в оболочке recovery применялся временный обход:

```sh
echo '' > /proc/sys/kernel/modprobe
```

Он относится только к текущему сеансу recovery и не является обязательной настройкой Firefox OS.

Если проверки прошли:

```powershell
& $adb reboot
```

## 10. Первый запуск и проверка

Дождитесь мастера первоначальной настройки; первый старт может быть дольше обычного. Не прерывайте его сразу извлечением аккумулятора.

Пройдите настройку и снова включите ADB. Проверьте:

```powershell
& $adb devices
& $adb shell cat /system/b2g/application.ini
& $adb shell cat /system/b2g/platform.ini
& $adb shell getprop init.svc.b2g
```

Последняя команда должна показывать running. Затем вручную проверьте экран, сенсор, звук, Wi-Fi, Bluetooth, NFC, камеру, звонки и мобильную передачу данных с вашей SIM. Успешная загрузка не доказывает исправность всех функций.

Сначала выставьте правильные дату и время. Ошибки HTTPS также могут быть связаны со старыми сертификатами и возможностями Gecko. Не отключайте проверку сертификатов глобально.

Сотовая связь зависит от диапазонов Fx0, оператора, APN и сетевого режима. Обновление системы не добавляет аппарату новые радиодиапазоны. При необходимости выбирайте доступный GSM/WCDMA/LTE-режим через настройки и задавайте APN своего оператора; не меняйте произвольные NV-параметры модема.

Русский язык интерфейса не гарантирует исправных шрифтов и русской клавиатуры в этой архивной сборке. На нашем телефоне они исправлялись отдельно после установки. Этот гайд устанавливает исходную 2.6, без наших последующих шрифтов, обоев, браузерного прототипа и механизмов сохранения изменений после сброса.

## 11. Если возникли проблемы

**ADB пустой:** проверьте режим USB, включённую отладку, кабель и драйвер. После первого запуска отладку может понадобиться включить заново.

**Fastboot пустой:** проверьте ручной вход Volume + с подключением USB и отдельный драйвер Bootloader Interface.

**Чёрный экран или повторяющаяся загрузка:** вернитесь в fastboot и временно запустите тот же TWRP. Проверьте права b2g, структуру webapps, свободное место, факт установки fxup и его boot. Не стирайте загрузочные разделы в попытке исправить профиль.

**Bluetooth/NFC не включаются:** проверьте установку fxup и отсутствие ошибок копирования/записи boot. Не прошивайте произвольный boot от Flame или другой модели.

**Сайты считают браузер устаревшим:** это ограничение старого Gecko. Данный переход 2.0 → 2.6 его до современного движка не обновляет.

## 12. Откат

Предпочтительный путь - загрузить временный TWRP через fastboot и восстановить СВОЮ согласованную резервную копию Boot, System и Data, сделанную перед установкой. Для полного возврата нужны все три: только старый каталог b2g не отменяет изменения boot и Bluetooth/NFC-библиотек.

Если использовались сырые образы из раздела 8, убедитесь в совпадении модели, целостности файлов и том, что это одна согласованная точка снимка. В fastboot:

```powershell
& $fastboot getvar product
& $fastboot flash boot "$backup\boot-before26.img"
& $fastboot flash system "$backup\system-before26.img"
& $fastboot flash userdata "$backup\userdata-before26.img"
& $fastboot reboot
```

Запись userdata уничтожает данные, появившиеся после снимка. При ошибке любой прошивки остановитесь и сохраните вывод; не продолжайте наугад. Не прошивайте aboot, модем или индивидуальные разделы ради обычного отката версии ОС.

Если снимок system содержал изменённый Dirty COW run-as, восстановите его исходное содержимое из своего run-as-original через TWRP перед окончательной загрузкой, сохранив исходные права и SELinux-метку файла.

Восстановление LAF - отдельная операция возврата LG Download Mode. Для обычного отката Firefox OS оно не требуется. Пока LAF обнулён, сохраняется удобный вход в fastboot. Возвращать LAF следует последним, только своим проверенным laf.img и после проверки рабочего способа восстановления. Простое восстановление Boot/System/Data LAF не возвращает.

Не публикуйте userdata, modemst, persist, factory и другие индивидуальные образы вместе с публичной прошивкой.

## 13. После успешной установки

Храните исходные резервные копии вне телефона. После проверки всех нужных функций можно удалить временные инструменты получения root и временное антивирусное исключение. Старые каталоги b2g-stock-2.0 и fx0-pre26-live не удаляйте до проверки отката и сохранности копий на компьютере.

Сброс к заводским настройкам очищает пользовательские данные и не означает возвращение с 2.6 на операторскую 2.0. Для возврата версии используется резервная копия.

Документ описывает выполненный нами путь установки на одном LGL25 и его ограничения. Это не гарантия одинакового результата на каждом экземпляре. Перед распространением комплект следует упаковать отдельно и повторно проверить на чистой операторской системе; текущую экспериментальную системную сборку с браузерным прототипом нельзя выдавать за исходную Firefox OS 2.6.
